# Watchlog — Change History (Steps 8–11) + Error Fix Log

Backend completion phase: health polling, metrics sampling, and the full Project/Service REST layer — plus every runtime/compile error we hit and fixed along the way.

---

## Step 8 — Health Poller ✅

**Goal:** periodically probe every registered service's health endpoint, record the result, and expose current status for the dashboard.

| File | Type | What it does |
|---|---|---|
| `WatchlogApplication` | modified | Added `@EnableScheduling` to activate the `@Scheduled` pollers |
| `service/HealthCheckService` | new | Polls every 30s (`@Scheduled(fixedDelay = 30_000)`): calls `baseUrl + healthCheckEndpoint` via a `RestClient` with **3s connect/read timeouts** (a hanging endpoint can't block the scheduler). 2xx → `UP`, anything else / exception → `DOWN`. Saves a `HealthCheckResult`. `currentStatus()` returns the latest result per service (`UNKNOWN` if never checked). |
| `controller/HealthController` | new | `GET /api/health` → `List<HealthStatusResponse>` |

**Response shape (`HealthStatusResponse`):** `serviceId (UUID), status (UP/DOWN/UNKNOWN), lastCheckedAt (Instant), responseTimeMs (Long)`.

## Step 9 — Metrics Poller + Queries ✅

**Goal:** sample metrics into the TimescaleDB hypertable and expose bucketed time-series for charts.

| File | Type | What it does |
|---|---|---|
| `service/MetricPointPoller` | new | Every 15s (`@Scheduled(fixedDelay = 15_000)`), writes synthetic `cpu_usage` + `memory_usage_mb` `MetricPoint` rows per service. Values are placeholders — swap for a real scrape (Micrometer/Prometheus) later. |
| `service/MetricQueryService` | new | Read side: defaults `from` = last hour, `bucket` = `1 minute`; runs the TimescaleDB `time_bucket()` native query (`MetricPointRepository.findBucketed`), maps each row `{bucket, avg(value)}` → `MetricQueryResponse.Point(Instant, Double)`. |
| `controller/MetricController` | new | `GET /api/metrics?serviceId=&metricName=&from=&to=&bucket=` → `MetricQueryResponse` |

**Depends on Step 2:** the `metric_points` table must be a hypertable for `time_bucket()` to work:
```sql
CREATE EXTENSION IF NOT EXISTS timescaledb;
SELECT create_hypertable('metric_points', 'timestamp');
```

## Step 11 — REST Layer (Projects & Services) ✅

(Step 10 — WebSocket live streaming — **deferred**, frontend comes later.)

**Goal:** full registration API with the rule *entities never cross the API boundary — always map `Entity → Response DTO`*, and `apiKey` is never echoed back.

### DTOs realigned to the entities
| DTO | Change |
|---|---|
| `ProjectRequest` | `name` → `projectName` (+ optional `projectDescription`; stored as `""` if omitted) |
| `ProjectResponse` | now `id, projectName, projectDescription, createdAt` (all `UUID`/`Instant`) |
| `ServiceRequest` | `name` → `serviceName` |
| `ServiceResponse` | now `id, projectId, serviceName, baseUrl, healthCheckEndpoint, createdAt` — **no `apiKey`** |

### Services & controllers
| File | Type | What it does |
|---|---|---|
| `service/ProjectService` | new | `create` (409 on duplicate `projectName`), `list`, `get` (404 if missing). Maps `Projects → ProjectResponse`. |
| `service/ServicesService` | new | `create` (404 if project missing, 409 on duplicate `serviceName` within project; `apiKey` auto-generated by `@PrePersist` when omitted), `listAll`/`listByProject`, `get`. Maps `Services → ServiceResponse`. |
| `controller/ProjectController` | new | `POST /api/projects` (201), `GET /api/projects`, `GET /api/projects/{id}` |
| `controller/ServicesController` | new | `POST /api/services` (201), `GET /api/services?projectId=` (optional filter), `GET /api/services/{id}` |

**Status codes:** `201` create, `400` validation, `404` missing project/service, `409` uniqueness conflict.

## 🐛 Error Fix Log (all debugging done during the build)

### 1. `LogDocument` used the wrong `@Id`
- **Symptom:** ES `id` field wouldn't map to `_id`; `findById`/`deleteById` would silently misbehave at runtime.
- **Fix:** `import jakarta.persistence.Id` → `org.springframework.data.annotation.Id`. Spring Data ES requires *its* annotation, not JPA's.

### 2. DTOs imported the wrong enum package (compile error)
- **Symptom:** `LogIngestRequest`, `LogQueryRequest`, `HealthStatusResponse` imported `com.datalog.watchlog.enums.*` — no such package exists; enums live in `com.datalog.watchlog.model.enums`.
- **Fix:** corrected imports to `model.enums`.

### 3. DTO ↔ model ID type mismatch
- **Symptom:** DTOs used `Long` IDs while the entities/document/event use `UUID` (and `String` in ES/Kafka).
- **Fix:** aligned all DTO IDs to `UUID` (web) / `String` (ES/Kafka). `LogIngestRequest.level` stays the `LogLevel` enum and is converted to `.name()` at the produce boundary.

### 4. `Services.apiKey` never auto-generated
- **Symptom:** column is `nullable = false` but `ServiceRequest.apiKey` is optional → omitting it failed on insert.
- **Fix:** added `@PrePersist void generateApiKey()` to `Services` — fills in `UUID.randomUUID()` when blank.

### 5. Missing uniqueness constraints
- **Fix:** `unique = true` on `projects.project_name`; `@UniqueConstraint(project_id, service_name)` on `services`.

### 6. Unused import
- **Fix:** removed stray `jdk.jfr.Timespan` import from `HealthCheckResult`.

### 7. `MetricPoint` composite key refactor (Step 2, Option A)
- **Symptom:** TimescaleDB `create_hypertable()` requires **every unique index/PK to include the partition column** `timestamp`. The surrogate UUID PK failed.
- **Fix:** dropped the surrogate id → `@IdClass` composite PK `(service_id, metric_name, timestamp)`. `timestamp` became the poller-set sampling time (no longer `@CreationTimestamp`). Side bonus: dedupes identical metric+timestamp inserts.

### 8. `jackson-databind` missing (compile error)
- **Symptom:** `cannot access com.fasterxml.jackson.core.type.TypeReference` — spring-kafka's `JsonSerializer`/`JsonDeserializer` depend on Jackson, declared optional by spring-kafka.
- **Fix:** added `com.fasterxml.jackson.core:jackson-databind` to `pom.xml` (version managed by Boot BOM).

### 9. Elasticsearch version mismatch (runtime 400)
- **Symptom:** `[es/indices.exists] Expecting a response body, status: 400` at startup.
- **Root cause:** Spring Data Elasticsearch **6.1** targets Elasticsearch **9.4.2**; compose ran **8.13.0**. The ES9 client requests were rejected by the 8.13 server.
- **Fix:** bumped compose image to `docker.elastic.co/elasticsearch/elasticsearch:9.4.2`. (Verified against the official [Spring Data ES version matrix](https://docs.spring.io/spring-data/elasticsearch/reference/elasticsearch/versions.html).)

### 10. Kafka `Instant` serialization failure (runtime)
- **Symptom:** `InvalidDefinitionException: Java 8 date/time type java.time.Instant not supported by default: add Module "jackson-datatype-jsr310"` at `LogIngestionService.ingest`.
- **Root cause:** spring-kafka's `JsonSerializer` builds its own **bare `ObjectMapper`** — it doesn't use Spring Boot's jsr310-configured one, so `LogEventMessage.timestamp (Instant)` had no handler.
- **Fix (two parts):**
  1. Added `com.fasterxml.jackson.datatype:jackson-datatype-jsr310` to `pom.xml`.
  2. `KafkaConfig` now builds a **dedicated `kafkaObjectMapper()`**: registers `JavaTimeModule` and disables `WRITE_DATES_AS_TIMESTAMPS` (ISO-8601). Both the producer `JsonSerializer` and consumer `JsonDeserializer` use it — fully independent of Boot's web-layer mapper.
- **Restart note:** because `pom.xml` changed, a plain re-run isn't enough — full rebuild + restart (IntelliJ *Rebuild Project*, or `mvnw clean install`).

### 11. `steps.md` typo
- **Fix:** hypertable SQL referenced `metric_point` → corrected to `metric_points` (the actual table name).

## Resulting API surface (at the end of Step 11)

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/projects` | create project |
| GET | `/api/projects` / `/api/projects/{id}` | list / get project |
| POST | `/api/services` | create service |
| GET | `/api/services` (`?projectId=`) / `/api/services/{id}` | list / get service |
| POST | `/api/logs` | ingest log (→ Kafka → ES), 202 |
| GET | `/api/logs` | search logs (serviceId/level/from/to/keyword/page/size) |
| GET | `/api/health` | current health of all services |
| GET | `/api/metrics` | bucketed metric time-series |

Testing commands for every endpoint live in **`apistest.md`**.
